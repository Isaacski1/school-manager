## Summary of Evidence from Code Inspection

### Local Persistence
- Attendance state saved locally in `handleChange` → `scheduleDraftSave` → `StudentAttendanceDraftStorage.saveDraft`.
- 1000ms debounce via `setTimeout` in `scheduleDraftSave`.
- Draft version increments via `draftVersionRef.current += 1`.
- LocalStorage key generated by `StudentAttendanceDraftStorage.getDraftKey`.

### Offline Save
- When `navigator/network status = offline` (`isOnline` false), `handleSave` calls `StudentAttendanceDraftStorage.saveDraft` and **does not** call `db.saveAttendance`.

### Online Save
- When online, `handleSave` constructs an `attendanceRecord` and calls `db.saveAttendance(attendanceRecord)`, preserving existing online behavior.

### Reconnection
- `useEffect` with dependencies `[isOnline, schoolId, selectedClassId, date, schoolConfig.currentTerm, schoolConfig.academicYear]` triggers on reconnection.
- Loads draft via `StudentAttendanceDraftStorage.loadDraft`, validates context, calls `syncDraft` which attempts `db.saveAttendance`.

### Failure Protection
- In `syncDraft`, if `db.saveAttendance` throws, the `catch` block sets `syncStatus = "error"` and **does not delete** the local draft.

### Success Protection
- After successful `db.saveAttendance`, the code reloads the draft and checks if version, timestamps, and context match; only then does it call `StudentAttendanceDraftStorage.deleteDraft`.

### Reload Recovery
- On mount, the "Draft recovery on context change" `useEffect` loads the draft from localStorage and restores `presentIds`, `isHoliday`, `holidayReason`.

### Context Isolation
- Storage key includes `schoolId`, `classId`, and `date` (e.g., `school-manager-student-attendance-draft-sch123-class456-2026-10-08`). Different class, date, or school yields different keys.

### Multi-tab Protection
- Storage event listener monitors changes.
- `hasStoredRevisionChanged()` compares versions; if an external draft is newer, it sets `externalDraftChanged = true`.
- Before saving/syncing, the code checks this flag and aborts if true, prompting user to review external changes.

### Activity Logging
- Offline local save: **No** call to `logActivity`.
- Successful backend sync: `logActivity` called in the online save branch of `handleSave` and in `syncDraft` on success.
- Failed backend sync: No successful-save `logActivity` is called; only error logging to console.
